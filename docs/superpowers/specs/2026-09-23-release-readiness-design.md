# CDriveCleaner 发布收口设计

## 目标

在不扩大清理范围、不触碰真实系统缓存的前提下，修复当前发布阻塞问题并生成可验证的 Windows 单文件安装包。

## 范围

本轮包含：

1. 修正系统临时目录发生部分删除失败时的结果语义，保留已释放字节并标记为部分完成。
2. 让源码运行和 PyInstaller 单文件运行都把清理日志写入稳定、可访问的位置。
3. 阻止扫描或清理过程中直接关闭窗口导致任务状态丢失；关闭请求先触发取消，任务结束后再允许退出。
4. 将运行依赖与测试、打包依赖分离，并同步 README 中的开发和打包命令。
5. 运行自动化验证、全新打包和 EXE 启动冒烟。

本轮不包含：

- 新增扫描器或扩大现有清理目录范围。
- 对真实浏览器、微信、系统缓存或回收站执行删除。
- UI 视觉重构、安装程序、自动升级、代码签名或新增图标。

## 设计

### 部分失败结果

`CleanExecutor._clear_temp_contents()` 在递归处理中继续累计成功删除文件的字节数。只要至少删除了一项且随后出现读取或删除错误，就抛出携带 `freed_bytes` 的 `PartialCleanupError`；完全未删除且失败时仍以失败处理。执行器继续保留该清理项供用户重试，不加入 `removed_ids`。

这与普通目录和回收站目录已有的部分完成语义保持一致，UI 无需引入新的结果类型。

### 持久日志目录

新增运行目录解析规则：

- Windows 正常运行及打包运行：优先使用 `%LOCALAPPDATA%\CDriveCleaner\logs`。
- `%LOCALAPPDATA%` 缺失或目录创建失败时：回退到 `%TEMP%\CDriveCleaner\logs`。
- 测试通过注入环境变量和临时目录验证，不写真实用户日志目录。

不再依据 `__file__` 推导日志目录，因为 PyInstaller one-file 模式下该路径属于临时解包目录。

### 窗口关闭协议

`AppWindow` 注册 `WM_DELETE_WINDOW`：

- 空闲时立即关闭。
- 扫描或清理进行中时，提示任务仍在运行。
- 用户确认退出后设置取消标志、进入“正在取消”状态，并等待 worker 回调完成后销毁窗口。
- 用户拒绝时继续当前任务。

后台回调在窗口进入关闭流程后不再弹出完成对话框，避免退出过程中的无效 Tk 调用。取消仍是协作式取消，正在执行的单个文件系统操作不会被强制终止。

### 依赖与构建

`requirements.txt` 只保留运行所需的 `customtkinter`。新增开发依赖文件，包含 `pytest` 和 `pyinstaller`。README 分别说明源码运行、测试和打包的安装命令。

继续使用现有 `build.spec` 生成 `dist/CDriveCleaner.exe`。本轮不强制 UAC 提权，避免应用一启动就获得管理员权限；需要管理员权限的项目继续由现有权限检查明确报告。

## 错误处理

- 日志主目录不可用时尝试临时目录；两处都失败则让现有清理失败提示显示具体异常。
- 关闭流程只设置取消标志，不强杀线程，避免目录删除执行到一半时进程被主动终止。
- EXE 冒烟失败视为发布阻塞，不交付旧包冒充新构建。

## 测试与验收

先写失败测试，再实现：

1. 临时目录删除一个旧文件后另一个文件失败，结果为 `partial_count == 1` 且保留已释放字节。
2. 日志目录在配置了 `LOCALAPPDATA` 时稳定落入应用目录；缺失时走临时目录回退。
3. UI 关闭协议通过隔离的状态/回调测试验证空闲关闭、忙碌取消和完成后关闭。
4. `requirements.txt` 不再包含测试和打包工具，开发依赖文件包含它们。

发布验证：

- `py -m pytest -q`
- `py -m compileall -q src tests`
- `git diff --check`
- `py -m PyInstaller --clean --noconfirm build.spec`
- 启动新 EXE，确认进程保持运行且主窗口可创建，然后正常关闭；不执行扫描或清理。
