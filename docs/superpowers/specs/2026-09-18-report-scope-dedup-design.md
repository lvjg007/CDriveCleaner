# 报告项范围与物理路径去重设计

## 背景

扩展名汇总把多个文件的总大小挂在单个样例路径上，整棵应用目录也可能被当作缓存删除；同时多个扫描器会对同一物理路径产生不同 ID。三类问题都会让用户看到的空间和实际操作不一致。

## 设计

- 扩展名汇总明确标记为不可删除报告项，样例路径只用于定位，不进入安全、深度或勾选清理队列。
- 对已知整棵应用数据目录（微信、Steam、Telegram、Docker、JetBrains、Spotify/OneNote 等）生成报告项；只有明确的缓存子目录保持可清理。
- 编排层先按 ID 去重，再用不解析符号链接的规范化路径键去重。同一路径冲突时优先保留不可删除项，其次保留更保守的推荐级别。
- 清理目标再做父子目录归并：报告父项继续展示；同时可删除时只执行最浅的真实目录，避免父目录递归清理后子项再次计数。
- 占用图只汇总可删除且已归并的有效目标，保持与确认框、dry-run 和实际释放空间一致。

## 验收

- 同一物理路径的不同 ID 最终只出现一条结果。
- 报告项不会被三条清理入口选入。
- 应用整目录报告项不可删除，明确缓存目录仍可删除。
- 同时选择可删除父子目录时只产生一个有效删除目标，报告父项和可清理子项仍可同时展示。
