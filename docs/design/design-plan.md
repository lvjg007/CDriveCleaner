# Design Plan — CDriveCleaner 主界面 v1

## 1. Subject

- 产品：CDriveCleaner，Windows C 盘手动清理工具（Python + CustomTkinter 桌面端）
- 受众：本机用户，自己清理自己的电脑；非专业运维，对系统路径不熟，**最怕误删**
- 本文件要完成的单一任务：让用户在一屏之内**看懂空间去哪了**，并**安全地勾选与执行清理**
- 假设与待确认：窗口维持 1400×780 可缩放（不拉齐到 1440×900 画布，桌面窗口无需固定画布）；深色模式继续跟随系统

## 2. Tone

- surface: `b_end`
- 气质：`utilitarian-enterprise` —— 工具型，信息密度优先，克制、无装饰
- 参考气质：Ant Design Pro 的后台列表页（允许列表）；明确拒绝 Dribbble 炫彩 dashboard

## 3. Token

**偏离说明**：B 端轨原表有 `sidebar_bg: #001529`。本产品是**单窗口单任务工具**，没有多模块导航，硬加侧栏只会增加无效导航 —— 故不设侧栏，改用顶栏 + 分组工具条（见 Anti-Slop 修订 B4）。

### Typography

- body：`Microsoft YaHei UI` 13（**偏离说明**：B 端轨建议 `PingFang SC`，该字体为 macOS 专属，Windows 端不可用；`Microsoft YaHei UI` 是 Windows 中文正文的等价选择，且不属于禁用清单）
- data：`Consolas` 12，用于路径与大小列（**偏离说明**：轨内建议 `SF Mono`，同为 macOS 专属，`Consolas` 是 Windows 自带等宽）
- scale：12（caption）/ 13（body）/ 15（section）/ 20（page title）
- 禁止：Inter、Roboto、Arial、system-ui 作中文正文 —— 本方案未使用

### Spacing / Radius

- spacing_allowed: `[4, 8, 12, 16, 24, 32]`（无 13/18/22 等随意值）
- radius: button `6` / card `8` / tag `4` / max `8`
- 表格行高 `34`（**偏离说明**：轨内建议 48–52 是 Web 后台值；桌面端鼠标精度更高、数据更密，34 是同类桌面工具的经验值）
- 触控目标：工具条按钮高 `32`，低于 44 —— 桌面鼠标场景，**不适用**触控底线；键盘可达性由快捷键（空格/回车切换勾选、Shift+滚轮横滚）承担

- regions 列表（与 `cleanup-list.page.ui.yaml` 一致）：
  1. `overview_bar` — 语义容量条 + 管理员徽标 + 主题切换（Signature 载体）
  2. `toolbar` — 三组：扫描 / 清理 / 查看
  3. `filter_bar` — 批量选择 + 分类筛选 + 排序
  4. `data_table` — flat table，无 card 外包
  5. `status_bar` — 已选合计 + 进度 + 当前扫描器
  6. `empty_state` — 未扫描时的引导态（替换 data_table 区域）

## 5. Signature

- 元素：**一条语义容量条，和三档语义色贯穿全屏**
- 落地规则：
  - 容量条按已用率取三档色：<70% success / 70–90% warning / >90% danger，同时永远带文字百分比（**状态不只靠颜色**）
  - 同一条 `success / warning / danger` 色阶复用于「建议」列的徽标（● 建议删除 / ◐ 可选 / ○ 不建议）与行底色
  - 克制：全屏只有这一个"视觉重量"元素；不做指标数字墙、不做渐变、不做阴影

## 6. Differentiation

相对 AI 默认的 dashboard（4 等宽 KPI 横排 + 卡片阴影墙 + 紫蓝渐变），本方案是**单张 flat table + 唯一 primary 按钮 + 描边分区**，语义色只出现在"风险"和"容量"这两件真正需要判断的事上，不做任何装饰性指标展示。

## Anti-Slop Review

- 日期: 2026-09-27
- surface: b_end

**命中项与修订：**

| 项 | 命中 | 修订 |
|----|------|------|
| A1 | 否 | 主正文 `Microsoft YaHei UI`，数据 `Consolas`；未使用 Inter / Roboto / Arial / system-ui |
| A2 | 否 | 主色 `#1677FF`，无靛紫主色、无紫蓝渐变 |
| A3 | 否 | 未命中 AI 三套默认皮：非紫蓝渐变 SaaS 落地页、非 4 等宽 KPI dashboard、非霓虹深色侧栏 |
| A4 | 否 | Layout 含本 brief 特有结构：语义容量条 + 三组工具条 + 空态引导 + 状态栏，换 brief 不成立 |
| A5 | 否 | Signature（语义容量条）承载真实信息（已用率），非纯装饰 |
| A6 | 否 | Differentiation 一句话可述（见 §6） |
| B1 | 否 | 列表为 flat table，无 card 外包 |
| B2 | 否 | 非 dashboard，不做 KPI 横排；容量信息是**单条**容量条，不是 4 等宽 |
| B3 | 否 | 全屏零阴影，分区一律 `1px #E8E8E8` 描边 |
| **B4** | **是** | 轨内要求侧栏 200–208px。**修订**：本产品无多模块导航，强行加侧栏属于为形式凑结构。已在 §3 Color 与 §4 Layout 说明以「顶栏 + 分组工具条」替代，并保留说明文字备查 |
| B5 | 否 | 信息密度偏运营工具（行高 34、13px 正文、路径列常驻），非 SaaS 大留白 |
| B6 | 否 | 每屏 primary 按钮 1 个（仅「开始扫描」）；清理类用 danger 描边，查看类用 ghost |

**额外自查（本次特有风险）：**

- 行底色三档（琥珀/红/灰）与斑马纹会互相打架 → **取舍：放弃斑马纹，改用语义行底色**。理由是斑马纹只为"不串行"服务，而语义底色同时服务"不串行"和"看出风险"，信息量更大。
- 语义色必须配文字符号（● ◐ ○ / 已用百分比），避免色觉障碍用户丢信息 —— 符合 design-shared 的 a11y 底线。

- 结论: **PASS**
