# IA Draft — CDriveCleaner

> Phase 0 产出。从 brief 推导，**禁止**套用固定后台页面清单。

## Brief 摘要

- 原文要点：「整体优化下产品 UI，直接在原先上修改即可」。产品为 Windows C 盘清理工具，已具备扫描/勾选/清理/导出/占用图全部能力，本轮只做界面层优化，不改能力边界。
- 产品类型：B 端（工具型桌面端）。判据：高密度表格 + 批量操作 + 使用者就是本机操作者，不是消费者内容消费场景 → `b_end`。
- 首批范围：主界面（扫描结果列表 + 工具条 + 状态栏）的视觉与信息层级重构。

## 1. 核心实体

| 实体 | 说明 | 来源 |

## 2. 角色与目标

| 角色 | 主要目标 | 来源 |
|------|----------|------|
| 本机用户（自己清理自己的电脑） | 在**不误删**的前提下尽快释放 C 盘空间 | 推断·待确认（产品无登录/多角色概念） |

## 3. 关键任务链

### 任务链 #1 — 知道空间去哪了

```text
[本机用户] 要 [判断 C 盘为什么满] → 需要 [看到各分类占用与可释放量排序] → 列表页（b_list_page）
```

### 任务链 #2 — 安全地删

```text
[本机用户] 要 [释放空间又不怕删错] → 需要 [先勾选、看清风险、再确认、最后看结果] → 列表页 + 确认弹窗 + 结果摘要
```

### 任务链 #3 — 判断某一项该不该删

```text
[本机用户] 要 [评估单条结果] → 需要 [看到完整路径、说明、原因、风险级别] → 列表页行内 + 悬停详情
```

### 任务链 #4 — 留档与复盘

```text
[本机用户] 要 [把结果带走或看整体占用] → 需要 [导出 CSV / 分类占用图] → 次级动作，非独立页
```

## 5. Scope Out（明确不做）

- **设置页**：产品没有可配置项，做一个设置页只是为了"看起来完整"。
- **历史记录页**：清理结果已落 `logs/`，本轮不做浏览界面。
- **定时/后台任务页**：产品明确承诺"只手动扫描、无后台常驻"，加调度页会违背产品立场。
- **独立详情页**：单条信息量小，用行内 + 悬停即可，拆页反而增加跳转成本。
- **分类占用图（Treemap）**：已是独立窗口，本轮不纳入。

## 推导依据（必填）

只有一页，是因为这个产品的**全部工作都发生在同一张表上**：用户扫完就在这张表里判断、勾选、执行。任务链 #1/#2/#3 共享同一份数据、同一屏视野，拆成多页只会制造来回跳转。真正的信息架构难点不在"有哪些页"，而在**一屏之内如何让"安全删"和"危险删"一眼可分**——所以本轮的设计重心放在工具条的主次分组、风险语义色和空态引导上，而不是增加页面。任务链 #4 是收尾动作，挂在工具条次级位即可，不配独立页。
