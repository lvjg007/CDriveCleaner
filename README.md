# CDriveCleaner

面向 Windows 的**磁盘手动清理工具**：选盘扫描可释放空间，预览后再删，默认本地运行、不上网。

这是一个面向真实 Windows 文件系统的清理器：扫描结果来自当前机器上的实际路径，执行清理会真实删除文件、清空明确的缓存目录或调用系统回收站 API。它覆盖已知垃圾位置，不承诺替代全盘取证工具；每次清理前应先查看路径、推荐级别和模拟日志。

> Python + CustomTkinter GUI，可用 PyInstaller 打成单文件 exe，目标机无需安装 Python。

## 为什么做这个

C 盘爆红时，系统自带清理不够细，第三方工具又常「一把梭」。本工具强调：

- **只手动扫描**，没有定时任务、没有后台常驻
- **每条结果带推荐标签**（建议删除 / 可选 / 不建议）和原因
- **先预览、再勾选、再清理**；支持模拟清理（dry-run）
- **硬排除** `System32`、`WinSxS` 等关键路径，降低误删风险
- **隐私**：不上传任何数据；日志只写在本机
- **范围明确**：系统文件、应用数据根目录和报告项只展示，不直接删除
- **谨慎处理系统目录**：WebCache、Windows 日志、Prefetch 和 Defender 历史默认只报告，避免整目录递归删除数据库或系统状态
- **可扫其它盘**：顶部选盘，容量条与扫描类别跟随；不适用于该盘的扫描器会明确跳过并说明原因，而不是把别的盘的结果报成本盘的

## 功能一览

### 扫描与清理

| 能力 | 说明 |
|---|---|
| 手动扫描 | 一键扫目标盘（默认 C 盘）的常见可清理项 |
| 选盘扫描 | 顶部可选任意固定盘（C:/D:/E:…），容量条与全部扫描类别跟随所选盘；切盘即清空结果并提示重扫 |
| 盘范围判定 | 每个扫描器声明自己适用于哪些盘：跟盘的（回收站/临时文件/大文件…）、只跟 Windows 的（更新缓存…）、只跟用户目录的（AI 工具数据/家目录残留…）；不适用的一律跳过并在状态栏说明数量 |
| 快速扫描 | 跳过微信 / 重复文件 / 大文件等慢项，先出结果 |
| 安全 / 深度 / 自定义 | 一键清建议项、深度项，或只清勾选项 |
| 模拟清理 | dry-run：只记日志、不真删 |
| 删除方式 | 普通文件可勾选「进回收站」以便恢复；已在回收站中的内容只能清空且不可恢复 |
| 新鲜文件保护 | 临时类清理跳过 24 小时内新建/修改的文件 |
| 报告项保护 | Space Hogs、扩展名汇总、未拆分的应用整目录，以及 AI 工具的凭据与活跃状态库只展示，不进入清理队列 |
| 重解析点保护 | 目录 junction / 符号链接一律不可删除 —— 删它会顺着链接打到目标目录（`Application Data` 指向 `AppData\Roaming`），且不参与大小统计、不能被当作父目录折叠子项 |
| 系统盲区报告 | WinSxS、事件日志等落在硬排除规则里的位置，走独立的只读测量通道展示量级，并给出官方处理方式；测量通道与删除保护相互独立 |
| 页面文件定位 | 读注册表 `PagingFiles` 找实际位置（含 `?:` 系统托管时逐盘探测），不写死 C 盘；不属于当前目标盘的报 0 字节并注明不占本盘空间 |
| 卷影副本报告 | 还原点/卷影副本按卷归属，只报目标盘那一个；非提权测不到时如实标注「需管理员」，绝不用 0 冒充测量结果 |
| 包仓库降级 | Maven / Gradle / Cargo / NuGet / go / pnpm 等标准包仓库可勾选但默认不勾 —— 删除只意味着下次构建重新下载，不丢数据 |
| 重复路径去重 | 同一物理路径由多个扫描器命中时只保留一条结果，避免重复统计 |
| 别名路径去重 | `%TEMP%` 常是 8.3 短名（`C:\Users\LVJING~1\...`），与 `C:\Users\lvjingang\...` 指同一目录；按文件系统标识而非字符串判重，避免同一目录被量两遍 |
| 重叠目录归并 | 同时选择可删除的父子目录时只执行父目录，确认金额和占用图按有效范围计算 |
| 跨盘删除闸门 | 不属于目标盘的条目在扫描层就被丢弃，执行层再独立复核一次；跨盘标记只对「仅报告」条目开放，杜绝「在 D 盘勾选、实际删掉 C 盘文件」 |
| 扫描时限提示 | 扫描器或目录遍历达到时间上限时标记“部分结果”，清理确认会保留提醒 |

- 导出扫描结果 CSV

### 多盘扫描

工具原本只认 C 盘，盘符写死在几十个地方。现在顶部可以选任意固定盘，
但「支持扫别的盘」真正的难点不是加一个下拉框，而是回答一个问题：
**这个扫描器在这个盘上到底有没有意义？**

答案分三类，写错了会静默产出错误结果而不是报错：

| 范围 | 含义 | 例子 |
|---|---|---|
| 任意盘 | 自己按目标盘适配根目录 | 回收站、临时文件、大文件、重复文件、空目录、占空间报告 |
| 仅系统盘 | 只在装了 Windows 的盘上有意义 | Windows 更新缓存 |
| 仅用户目录所在盘 | 读 `Path.home()`，用户目录只在一个盘上 | AI 工具数据、家目录残留、浏览器缓存、微信 |

判定的关键是第二、三类都**不按盘符判断，而按盘的属性判断**：
用户目录可以被搬到 D 盘，Windows 也可以装在 D 盘。所以判据是
「这个盘上有 `\Windows` 吗」和「这个盘是 `Path.home()` 所在的盘吗」。

**为什么第二、三类必须跳过，而不是照跑一遍？**
读 `Path.home()` 的扫描器在 D 盘重跑，会把 C 盘的家目录垃圾**原样再报一遍**。
用户以为在 D 盘发现了 20 GB 垃圾，其实那 20 GB 全在 C 盘 —— 这就是**假重复**。
真机实测：同一台机器 C 盘 391 项，D 盘 124 项，D 盘跳过 14 个扫描器。

**跨盘条目一律不可删除。** 编排层按目标盘过滤一遍，执行层在真正落盘删除前
再独立复核一次 `item.drive != target_drive()`。跨盘标记（`cross_drive`）只对
「仅报告」条目开放 —— 可删除条目带上它，就等于给「在 D 盘勾选、实际删掉
C 盘文件」开了口子，`CleanItem.make` 直接把这个组合抹掉。

**非系统盘与 C 盘用同一套推荐规则**，不额外收紧：D 盘的下载目录和 C 盘的
一样是用户自己的东西，没有理由因为它在数据盘上就改变建议级别。

几处只有多盘之后才会暴露的细节：

- **回收站按卷独立**：`C:\$Recycle.Bin` 与 `D:\$Recycle.Bin` 是两个互不相干的
  位置。所以只报目标盘那一个，不做跨盘汇总 —— 汇总会让用户在 D 盘上看到 C 盘的
  数字，清空之后又对不上。清空时也把盘根传给 `SHEmptyRecycleBinW`，只清自己那个。
- **遍历型扫描器的根必须落在目标盘上**：`large_files` 的候选里曾写死
  `C:\Users\Public\Downloads`，用户目录一旦被搬到 D 盘，选 D 盘扫描时它会照样去
  遍历 C 盘那个目录。现在这条不变量由 `roots_for_search_scanner` 统一兜住，
  跨盘候选直接丢掉 —— 多扫一个目录只是慢，把 C 盘的文件报成 D 盘的垃圾才是真问题。
- **硬排除规则要盘无关**：`D:\Recovery`、`E:\System Volume Information` 和 C 盘的
  同名目录一样受保护。匹配位置从「绝对路径第 N 段」改成「盘符之后的第一段」。
- **非法盘符不退回 C 盘**：`drive_root("")` 抛 `ValueError`，
  `set_target_drive("垃圾")` 是空操作而不是重置。界面显示 D、实际扫 C，
  对删除工具是最坏的失效方式。
- **同一目录的两种写法会双倍计量**（排查多盘根目录时顺带发现的旧 bug）：
  `%TEMP%` 在真机上就是 8.3 短名 `C:\Users\LVJING~1\AppData\Local\Temp`，
  与家目录推导出的长名指的是**同一个目录**。字符串比较判不出重复，
  于是「系统临时文件」把同一个目录量两遍、报两条 —— 实测 1185.6 MB 会显示成
  2371 MB，清理后释放的空间也对不上。去重键改用与「删除目标去重」同一套的
  `canonical_path_key`（解析重解析点 + 8.3 别名），候选里保留长名用于展示。

### AI 工具数据

覆盖 Claude Code、OpenAI Codex CLI、Cursor、Kiro、Void、Windsurf、Trae、Zed、PearAI、
Qwen Code、Gemini CLI / Antigravity、Cline / Roo Code / Continue / Copilot Chat，
以及 Aider、Codeium、Tabnine、Augment、Cody、通义灵码等 CLI 工具写出的日志、
临时目录、更新包残留、Electron 缓存与会话历史。

**按 AI 客户端分列**：结果不塞进一个笼统的「AI 工具数据」桶，而是拆成
`AI · Claude Code` / `AI · Codex` / `AI · Cursor` / `AI · Qwen Code` … 等分类，
在分类下拉里可以逐个客户端筛选、逐个勾选。

粒度刻意做到**子目录/单文件**而不是整个工具目录 ——
`~/.codex` 里 `logs_2.sqlite` 是纯日志，而 `sessions/` 是会话历史，两者必须区别对待。

分三层展示风险，**三层都可以勾选** —— 分层只表达代价高低，删与留由你确认：

| 级别 | 内容 | 默认 |
|---|---|---|
| 建议删除 | 日志、临时目录、更新包残留、GPU / 代码缓存、遥测、崩溃转储、旧 `.bak` 残留 | 已勾选 |
| 可选 | 会话历史、编辑快照、插件、沙箱运行时、标准包仓库（Maven / Gradle / Cargo / NuGet / go / pnpm） | 不勾，清理时二次确认 |
| 不建议 | 编辑器活跃状态库、模型权重（Ollama / LM Studio / HuggingFace） | 不勾，理由里写明代价，确认后仍可勾 |

凭据类文件名（`oauth_creds.json`、`.credentials.json`、`settings.json`、`.env` 等）
不纳入扫描 —— 删它们省不出空间，只会让工具无法登录，属于纯损失。有独立兜底黑名单保证它们不会被产出。
- 空目录、重复文件、扩展名占用汇总
- **微信定制扫描**（个人/群聊 × 图片/视频/文件/缩略图等；聊天附件 ≠ 聊天记录）
- Space Hogs **仅报告**（休眠/页面文件、WSL/Docker vhdx、**WinSxS 组件存储**、**MSI 安装缓存**、VS/VC++ 安装缓存、**Windows 事件日志**）
- 应用整目录（微信、Steam、Telegram、Docker、JetBrains 等）未拆分前仅报告；明确的缓存子目录仍可单独清理

### 系统盲区报告

`C:\Windows\WinSxS`、`C:\Windows\System32\winevt\Logs` 这类目录落在硬排除规则里，
任何走常规测量的扫描器都看不见它们 —— 结果是 **C 盘上最大的东西反而长期是盲区**
（本机 WinSxS 实测 15.7 GB，旧版本只量到 86 KB）。

现在它们以「仅报告」形式出现在占空间报告里，并给出正确的处理方式：

| 位置 | 本机实测 | 正确处理方式 |
|---|---|---|
| `C:\Windows\WinSxS` | 15.7 GB（含硬链接，实际占用更小） | `Dism /Online /Cleanup-Image /AnalyzeComponentStore` 看可回收量，`/StartComponentCleanup` 清理 |
| `C:\$WinREAgent` | 1.95 GB | 可勾选；Windows 通常 10 天后自动清理，确认无进行中的更新后再删 |
| `C:\Windows\Installer` | 981 MB | 仅报告；删了会导致修复/卸载失败 |
| `C:\ProgramData\Package Cache` | 498 MB | 仅报告；VS/VC++ 修复时会用到 |
| `C:\Windows\System32\winevt\Logs` | 367 MB | 仅报告；应在「事件查看器」中清除 |

**测量与删除是两条独立的线**：报告通道（`measure_protected_dir`）绕过的只是
「遍历时跳过」，让数字能被看见；可删除性由 `CleanItem.deletable` 与
`is_deletion_protected` 两道闸门把守，报告通道不参与其中任何一道。
WinSxS 即便被标成可删，删除保护仍会拦下 —— 这条边界有专门的测试锁死。

WinSxS 有十几万文件，实测两种遍历方式都要两分钟以上，交互式扫描只能给
**有界下界**，此时理由里会写明「大小统计超时，实际不小于所显示的值」。
另外它内含大量与 System32 共享的硬链接，按文件大小累计会高估实际占用，
权威数字只能由 DISM 给出 —— 理由里也写清了这一点。

#### 页面文件：位置要查注册表，不能写死 C 盘

页面文件经常被挪到别的盘，写死 `C:\pagefile.sys` 的结果是**报告里根本没有这一项**，
看起来像漏扫、其实只是找错了地方。本机就是这个情况：页面文件在 `D:\pagefile.sys`
（11 GB），C 盘压根没有这个文件。

现在改为读注册表 `PagingFiles`：

- 值形如 `D:\pagefile.sys 4096 8192` —— 第一段是路径，后两段是初始/最大 MB，不是路径
- 值形如 `?:\pagefile.sys` —— **系统托管，注册表不记录它最终落在哪个盘**，
  只能逐固定盘根目录探测（`fixed_drive_letters()`）
- 落在**当前目标盘**的按真实大小报；目标盘一个都没有、但别的盘有时，
  报一条 0 字节说明项，理由里带上真实大小并注明「不占用本盘空间」

报 0 而不是真实大小是有意的：否则「已扫描」总量会虚高，用户会以为清了能省这么多。

#### 卷影副本 / 系统还原点：测不到就如实说测不到

这是 C 盘上最典型的「看不见的大户」，占用几 GB 到几十 GB，
但既不落在任何可遍历目录里（`C:\System Volume Information` 拒绝访问），
也不在普通扫描器视野内。**它的实际占用必须提权才能查询**，已用四条独立路径实测确认：

| 路径 | 非提权下的结果 |
|---|---|
| `vssadmin list shadowstorage` | 退出码 2，「你没有正确的权限，无法运行这个命令」 |
| `Get-CimInstance Win32_ShadowStorage` | HRESULT `0x80041014` 初始化失败 |
| `root\default:SystemRestore` | 退出码 1 |
| `C:\System Volume Information` | WinError 5 拒绝访问 |

所以这一项在非提权会话下**仍然出现**（0 字节 + 标注「需管理员」），
理由里写明用 `vssadmin list shadowstorage` 或「系统属性 → 系统保护」查看处理。
它消失的话，用户永远不会知道 C 盘上还有这么个吃空间的东西 —— 那正是它长期成为盲区的原因。

> **一个真实的坑**：`(Get-CimInstance Win32_ShadowCopy | Measure-Object).Count`
> 在权限不足时会返回 `0` —— 因为 CIM 的错误是非终止性的，被 `Measure-Object` 吞掉了。
> 看起来像「本机没有还原点」，实际上只是查询彻底失败了。
> 任何「有没有还原点」的结论都不能基于这个 0，这也是 `_query_shadow_storage_size()`
> 在测不到时返回 `None` 而不是 `0` 的原因。

### 家目录残留

覆盖**非 AI 软件**在用户目录里下载/生成的缓存、日志与备份。与「AI 工具数据」的分工是：
那边按 AI 客户端收口，这边按**残留类型**收口。

清单不是凭印象写的 —— 先遍历整个家目录找出「占空间且没有任何扫描器覆盖」的位置，
再逐层下钻把每个候选量准，最后才决定收哪些、算哪一档。每一项都在实机量过大小。

| 分类 | 典型内容 |
|---|---|
| 更新器残留 | `AppData\Local\*-updater` —— 各应用自动更新下载的安装包，实测 9 个目录约 1.6 GB |
| 扩展安装包缓存 | `CachedExtensionVSIXs` —— 已装扩展的下载副本，扩展本体已解压，删了不影响功能 |
| 编辑器缓存 | Trae CN / TRAE SOLO CN / Qoder 的 Cache、CachedData、GPUCache、崩溃转储、日志 |
| 包与构建缓存 | uv cache、electron、electron-builder、node-gyp、Dart pub、go-build、Gradle tmp/daemon/wrapper、SonarQube |
| 浏览器运行时 | Playwright / Puppeteer / rod / BurpSuite 下载的浏览器内核，agent-browser 临时配置，Android SDK |
| 日志与备份 | cc-switch 数据库备份、Kiro 代理日志、Postman 缓存、Clash Verge 更新缓存、Everything 索引库 |
| 家目录杂项 | 根目录散落的 `replay_pid*.log`、`*.dmp`、孤立安装包 |
| 已装扩展 | 编辑器 `extensions` 目录 —— **不建议**，删了功能会缺，建议在编辑器内管理 |
| 用途待确认 | TRAE SOLO 模块数据、pas 工作区等体积大但用途未定的目录，只列出来由你判断 |

同样分三层、**三层都可勾选**。「已装扩展」「用途待确认」落在「不建议」层，
理由里写明代价，确认后仍可勾。

**大小统计超时会标注**：小文件极多的目录在时限内只能量到一部分，
此时理由里会写「大小统计超时，实际不小于此值」。实测 `~/.trae-cn/extensions`
真实 1.69 GB，给 2 秒上限只量到 73 MB —— 差 23 倍的数字会直接把删/留判断带偏。

## 测试

```powershell
py -m pytest tests -v
```

测试里有一批是「盘范围」与「路径别名」的回归：它们断言的是**语义正确性**
而不是「代码能跑」—— 比如读 `Path.home()` 的扫描器在非用户盘上必须被跳过、
任何扫描器挑出来的根都必须落在目标盘上、`%TEMP%` 的短名与长名必须去重成一条。
这类错误不会抛异常，只会给出一份看起来完全合理的报告。

## 使用建议

1. 先选**目标盘**（默认 C 盘），再点 **开始扫描**（磁盘很大时可勾选 **快速扫描**）。
2. 看推荐列：**建议删除** 相对安全；**不建议** 默认不要勾。报告项不会进入清理队列。
3. 不确定时先勾 **模拟清理**，看日志里会删什么。
4. 需要可恢复时勾选 **进回收站**；不勾则为永久删除。
5. 微信相关：优先清缩略图 / 缓存 / 视频附件；「聊天记录库」勿轻易删。
6. 扫非系统盘时留意状态栏的「N 个扫描器不适用于本盘」—— 那是按盘属性正常跳过的
   （用户目录、Windows 安装都不在那个盘上），不是漏扫。

## 项目结构

```
CDriveCleaner/
├── src/
│   ├── main.py              # 入口
│   ├── app/                 # 编排（按目标盘挑扫描器 / 清理）
│   ├── scanners/            # 各类扫描器（可注册扩展，各自声明盘范围）
│   ├── cleaner/             # 执行删除 / dry-run / 回收站（含跨盘复核闸门）
│   ├── models/              # CleanItem 等数据模型
│   ├── ui/                  # CustomTkinter 界面与占用图
│   └── utils/               # 盘符基础设施、路径安全、新鲜度、回收站、日志等
├── tests/
├── docs/                    # 设计与实现计划
├── build.spec               # PyInstaller 配置
└── requirements.txt
```

架构简述：`UI → Orchestrator → Scanners → CleanItem → CleanExecutor`。

盘相关的判断集中在 `src/utils/drives.py`：枚举固定盘、判断哪个盘装了 Windows、
哪个盘放着用户目录，以及「当前目标盘」这个模块级状态（扫描器有 22 个，
逐个改签名噪音太大；需要隔离时用 `use_drive` 上下文管理器）。

新增扫描类别：实现 `Scanner` 子类并在 `src/scanners/registry.py` 注册即可。
**别忘了声明 `drive_scope`** —— 默认是「任意盘」，读 `Path.home()` 的扫描器
漏声明不会报错，只会在别的盘上把用户盘的结果再报一遍。
